Opening

Problem Statement

Manual or weakly protected justice case systems make it difficult to manage records, track workflow changes, and prove that sensitive case data has not been tampered with.

Operational challengeCase information must move across police, investigation, registry, and review stages.
Integrity challengeImportant changes must be traceable and verifiable.
We need a digital case management system that is easy to use, structured in storage, and strong in integrity verification.
User 1 should present this first.2 / 9
Opening

SMART Objective

To build a justice case management system that allows users to capture, process, store, and verify case records using Next.js, Node.js, TiDB, and blockchain, with traceable workflow actions and integrity checks during the project demonstration period.

SpecificDigital case capture, processing, storage, and verification.
MeasurableCases can be created, stored, and anchored successfully.
AchievableUses one integrated web stack and clear module separation.
RelevantSupports accountability and trust in justice workflows.
Problem first, objective second.3 / 9
System Flow

Best Team Order

  • 1. Next.js
  • 2. Node.js
  • 3. TiDB
  • 4. Blockchain
Next.js handles the interface, Node.js handles the logic, TiDB stores the full data, and blockchain provides proof of integrity.

Reason for this order: it follows the real system flow from user interface to backend logic to data storage to integrity verification.

User interface -> logic -> storage -> proof.4 / 9
